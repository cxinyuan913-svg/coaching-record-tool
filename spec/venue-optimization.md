# 場館優化建議

## 目的

部分學生可接受多個場館上課。新增一堂場館固定的課程時，系統自動檢查同一天是否有更集中場館的排法，減少當天往返場館的次數。

## 新增資料表

```
student_venue_options (id, student_id FK, venue_id FK)
```

一個學生可對應多筆記錄，代表該生可接受的場館清單。只有一筆代表場館固定；多筆代表有彈性。

## 觸發時機

新增一堂場館固定的課程時（該學生在 `student_venue_options` 只有一筆記錄）自動觸發檢查。

## 檢查範圍

只看同一天，不跨天檢查。

## 演算法

1. 撈出同一天所有 `status = scheduled` 且該學生在 `student_venue_options` 有多筆記錄的既有課程（這些是可調整的彈性排課）
2. 窮舉這些彈性課程所有場館組合（數量少，直接窮舉即可）
3. 篩掉時段衝突、以及違反新固定課程場館限制的組合
4. 從合法組合中找出「當天用到場館數最少」的排法
5. 若最佳排法與目前實際排法不同 → 產生建議

## 輸出與確認機制

這是「建議」而非自動執行——被建議調動的課程是已跟學生約好的，系統不能自行更改。使用者確認採用建議後，該堂課標記為「場館待確認」狀態，提醒使用者需親自聯繫該學生重新確認場館，待學生答應後才算定案。

```
優化建議：
本週三，王同學目前排在泰山（可選：泰山、三重），
新學生李同學只能在三重上課。
若把王同學改到三重，本週三只需跑三重一趟，
可省下一次泰山↔三重的往返。
[採用建議並標記待確認] [略過]
```
