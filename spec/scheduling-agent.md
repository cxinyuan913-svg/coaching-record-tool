# 找空檔排班 Agent

## 目的

學生提出時間需求（例如「下週一到五，台北」），系統自動比對既有行事曆，找出最省交通時間的候選時段，產生一段可直接複製給學生的訊息。

## 新增資料表

```
venue_travel_times (id,
                     venue_a_id FK, venue_b_id FK,
                     travel_minutes)
```

場館兩兩之間的固定車程對照表，同場館車程視為 0，不用建表查詢。

## 架構原則

LLM 只負責兩件事：解析學生的自然語言需求成結構化條件（日期範圍＋地區限制），以及把最終候選組成訊息文字。實際找空檔的運算邏輯用一般程式處理，不交給 LLM 推理，確保結果可預期、不會算錯。

## 候選時段演算法

**貼靠候選**（緊貼既有課程，交通最省）：

1. 撈出該範圍內、相關場館的既有 `lessons`（排除 `status = cancelled`）
2. 對每一筆既有課程，往外長出最多兩個候選時段：
   - 之後：從該堂結束時間開始算一段課程時長
   - 之前：往前推一段課程時長，結束時間對齊該堂開始時間
3. 場館判斷：
   - 候選跟錨點同場館 → 直接通過
   - 候選跨場館 → 檢查候選所在場館當天的連續時數（含同場館其他鄰接課程/候選加總），須 ≥ 120 分鐘才通過，否則剔除（去程回程換不到兩小時不划算）
4. 去重：不同課程生出的候選若時段完全相同，只保留一筆
5. 排除衝突：候選跟任何一筆既有課程（不限於用來生成候選的那一筆）重疊 → 剔除
6. 排除跟學生指定地區不符的候選

**專程候選**（該日在指定地區完全沒有既有課程可貼靠）：

只標記日期，不計算具體時段（沒有基準點可推算合理時間），由使用者自行決定時段，訊息中註明「需專程前往」。

## 輸出格式範例

```
貼靠候選（交通最省）：
・9/16(二) 19:00-20:00，動智羽球館（緊接既有課程）

專程候選（該日目前沒有其他排課）：
・9/17(三) 全天可談，需自行決定時段
```
